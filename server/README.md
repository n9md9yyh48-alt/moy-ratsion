# Защищённый анализ фотографий (заготовка backend)

**Статус: код готов для локальной проверки, НО сервер не развёрнут, платное распознавание в приложении не включено.**

GitHub Pages остаётся статическим сайтом и **не может запускать сервер**. Чтобы включить AI, потребуются отдельно размещённый HTTPS-backend, API-ключ провайдера и закрытый токен доступа. Согласовать расходы и выбор хостинга до включения.

## Как работает

- Сервер Node.js 22+, только стандартные модули Node, без внешних npm-зависимостей.
- `POST /api/analyze-meal`: JSON с `consent: true` и `image_data_url` (JPEG, PNG, WebP; base64).
- Запрос допускается только с серверным `AI_ACCESS_TOKEN` (Authorization: Bearer), и только с разрешённого Origin. Отклоняются крупные/несоответствующие формату изображения.
- Вызов OpenAI Responses API выполняется только сервером с `store: false`. Ответ обрабатывается как JSON по строгой схеме и повторно проверяется.
- Сервер **не сохраняет**, **не журналирует** фото, персональные записи, ключ или тело ответа. Никаких секретов в репозитории.
- `GET /health` возвращает только `ready: false/true`; не раскрывает секреты.

## Тесты — без реального API и без платных запросов

```sh
node --test tests/*.test.mjs
```

Тестовый провайдер полностью подменяется mock-функцией. Реальный `OPENAI_API_KEY` не нужен.

## Локальный запуск (только для разработчика)

1. Создать приватные переменные окружения `OPENAI_API_KEY`, `AI_ACCESS_TOKEN` (криптографически случайный, от 32 символов), `AI_MODEL` (например `gpt-4.1-mini`) и `AI_ALLOWED_ORIGIN`. Пример структуры в `.env.example` — там **нет реальных ключей**.
2. Запустить `node server/http.mjs`. Node сам не подхватывает .env без специального флага; не записывать секреты в GitHub.
3. На локальной машине сервер отвечает на `http://localhost:8787/health`, пока не указано иное в `PORT`.

**Не открывать HTTP напрямую в интернет.** Для внешнего доступа обязателен HTTPS и закрытый сервер.

## Ограничения перед продакшеном

- В текущем варианте `AI_ACCESS_TOKEN` — общий приватный токен; нельзя встраивать его в публичный JS, README или HTML. Необходим безопасный способ авторизации человека, прежде чем делать кнопку в публичном PWA.
- Лимит 3 запроса в минуту с одного IP и глобальный дневной лимит (по умолчанию 20) ведутся **в оперативной памяти**. Они сбрасываются при перезапуске и НЕ подходят для многопроцессного/многоузлового продакшена. Понадобится внешняя квота (Redis/БД/API gateway) и лимит оплаты у провайдера.
- Веб-приложение не имеет сейчас настроенного адреса API, учётной записи или платной подписки; **нет работающей кнопки AI**.
- Нужно выбрать хостинг, платёжный лимит, срок хранения данных у поставщика, способ авторизации, политику приватности и оценить расходы.
- Результат представляет **приблизительные диапазоны**, а не измеренную по фото калорийность. Нельзя без подтверждения человека сохранять его в дневник.
