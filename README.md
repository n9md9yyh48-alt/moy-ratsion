# Мой рацион — PWA для iPhone (3.0 beta)

Статическое PWA без платных сервисов. Откройте index.html для локального теста; для установки на iPhone опубликуйте папку на HTTPS-хостинге (например, GitHub Pages / Cloudflare Pages), затем откройте в Safari → Поделиться → На экран Домой.

## Дизайн 3.0 beta (10 ноября 2026)

Новый тёмный угольно-золотой интерфейс по выбранной пользователем концепции: крупное калорийное кольцо, текущее превышение или остаток относительно **настроенной** цели, полосы БЖУ, карточки приёмов пищи с сохранёнными фото (если были) и полноценно адаптированная нижняя навигация. Календарь, список блюд, формы, рецепты, отчёты, экспорт JSON и обмен по коду с ChatGPT сохранены.

- `theme-v3.css` — отдельный визуальный слой без внешних зависимостей/веб-шрифтов.
- `ui-v3.js` — читает калории и БЖУ из уже существующего рендера. Шкалы БЖУ показывают **долю энергии по макронутриентам в записанной еде**, а не выдуманные индивидуальные нормы. Никаких записей в localStorage этот модуль не делает.
- В `features-v12.js` изменена **только разметка списка приёмов пищи**; модель данных, ключ `moy-ratsion-v1`, редактирование, избранное и фото не изменены.
- `sw.js`: офлайн-кэш `moy-ratsion-v16`, включающий новый CSS/JS. `manifest.webmanifest`: тёмный фон установленного приложения.
- Добавлены проверки: 56 Node.js + 7 Playwright/Chromium E2E, в том числе для макета 390/320 px и неизменности сохранённых данных. [GitHub Actions](https://github.com/n9md9yyh48-alt/moy-ratsion/actions).
- Действующий адрес не менялся: <https://n9md9yyh48-alt.github.io/moy-ratsion/>. Другой адрес у Netlify пока не создан; подготовка [здесь](docs/netlify-setup.md).

Предыдущая версия 2.0 RC и её главные функции были **проверены пользователем на настоящем iPhone**: сохранность данных после обновления, обмен с ChatGPT в обе стороны и скачивание JSON. Новый дизайн 3.0 beta отдельно на iPhone **ещё не подтверждён**. Не переустанавливайте PWA и не удаляйте локальный дневник: перед проверкой новой версии достаточно существующей копии JSON.

## Текущий режим: бесплатно, вместе с ChatGPT

**Решение пользователя (9 ноября 2026):** вместо ещё одного платного ИИ внутри PWA использовать ChatGPT в отдельной беседе. Приложение выступает как **бесплатный локальный дневник** и поддерживает перенос записей из чата. Предварительно согласованный лимит OpenAI API $5 **не используется**: сервер Cloudflare не запущен, API и оплату не подключаем. Заготовки серверной части остаются в репозитории, но не подгружаются в публичном интерфейсе.

Что уже работает в текущем коде:

- Нижняя вкладка **«💬 В чат»** подготавливает текст за выбранный день или за 7 дней. Передача только вручную: пользователь копирует текст и вставляет в ChatGPT; приложение ничего само не отправляет.
- Ссылки и коды вида `#meal=...` и `meal:...` позволяют импортировать **один** приём пищи с проверкой даты и КБЖУ, обязательным подтверждением и защитой от повторов.
- **Разница Safari и установленного PWA:** если ссылка открылась в Safari, данные могут сохраняться в другом хранилище. На iPhone выводится предупреждение и возможность скопировать код для вставки в установленном PWA.
- В дневнике рядом с прогрессом показан приблизительный остаток до дневной цели; калории из фотографий остаются оценочными, и превышение цели — не основание пропускать еду.
- Временные фото и истории ChatGPT не передаются по сети приложением, локальный дневник хранится на iPhone. JSON-резервные копии остаются важны.

**Запуск отдельных AI-сервисов не нужен и не выполнялся.** На iPhone заново устанавливать PWA не требуется; обновлённая версия загружается при доступе к сети. Основные пользовательские проверки версии 2.0 RC на реальном iPhone завершены; новый интерфейс 3.0 beta ожидает визуальной проверки владельцем.

## Реализовано
- Локальный дневник питания, фото, калории, БЖУ и напитки.
- Учёт веса, график, просмотр и редактирование измерений; отчёт за 7 дней.
- Календарь: выбор даты, переход по дням и месяцам, просмотр дневника за любой день.
- Быстрое добавление недавних и избранных блюд без повторного ввода БЖУ.
- 100 ориентировочных рецептов (30 исходных + 70 дополнительных), поиск по названию, ингредиентам и избранному, добавление в дневник.
- Редактирование целей, резервная копия JSON, восстановление и удаление.
- PWA и кэширование для офлайн-доступа после первого открытия.

## Ограничения
- Фото **не распознаются ИИ**: расчёты вводятся вручную.
- Нет автоматической синхронизации между устройствами или прямого API-доступа к ChatGPT. Есть ручной проверенный обмен с ChatGPT по коду и копированию сводки.
- Данные и фото находятся в localStorage текущего браузера; при очистке данных браузера или удалении приложения они могут быть потеряны. Нет синхронизации или серверных копий. Регулярно экспортируйте резервную копию JSON.
- Версия 1.2 проверяет успех каждой записи. Если память переполнена, прежний дневник остаётся нетронутым. Автокопия создаётся только для небольших дневников (до 350 000 символов), при наличии свободной памяти; она остаётся на том же устройстве и **не заменяет** выгрузку JSON.
- Значения калорийности рецептов ориентировочные, не рассчитаны по точным граммовкам.
- Приложение не заменяет врача или диетолога.

### Ручная проверка после обновления
1. До обновления скачать резервную копию через «Отчёты» → «Скачать JSON».
2. Выбрать в календаре вчера и добавить блюдо; проверить, что оно не появилось в сегодняшнем списке.
3. Быстро повторить блюдо и добавить его в избранное; убедиться, что калории и БЖУ сохранились.
4. Создать запись веса, изменить дату или вес и удалить тестовое измерение.
5. Экспортировать JSON, проверить что файл скачался; при необходимости восстановить в другом браузере через настройки.

Состояние данных и фотографий НЕ загружается в GitHub. Приложение остаётся полностью локальным.

## Промежуточная сборка после 1.2 — доработка без переустановки

Пользователь решил не переустанавливать приложение на iPhone после каждого изменения. Разработка и автоматические проверки ведутся в GitHub, без обязательного тестирования на устройстве до финального релиза.

Добавлено:
- Офлайн-справочник 73 продуктов с **ориентировочными** калориями и БЖУ на 100 г/мл. В форме записи выбирается продукт и масса порции. Пищевая ценность готовых блюд зависит от состава и масла, поэтому значения следует сверять с этикеткой и фактической рецептурой.
- Кнопка копирования вчерашнего рациона на выбранную дату (без фотографий, с подтверждением).
- 100 рецептов, включая 70 новых со списками ингредиентов и способами приготовления. Поиск по ингредиентам показывает совпадения, но **не гарантирует**, что дома есть всё необходимое. У новых рецептов калории ориентировочные и не являются точным расчётом по фактической массе ингредиентов.
- Избранные рецепты, фильтры и постраничный вывод по 20 рецептов для удобства на смартфоне.
- Недельная диаграмма калорий и усреднённые БЖУ по заполненным дням; отсутствие записей **не означает** нулевое потребление.
- Информация о размере локального хранилища, количестве записей и фото.
- Строгая проверка дат, корректное различение ошибки сохранения и ошибки перерисовки интерфейса.
- «Мои продукты»: сохранение введённого продукта как локального шаблона с БЖУ на 100 г/мл, быстрый поиск, пересчёт порции, замена и удаление из справочника. Личные продукты входят в JSON-экспорт.
- Удаление фотографии из существующей записи о еде без удаления записи; обычные правки оставляют фото на месте.
- Усиленная проверка при восстановлении из JSON и локальной автокопии: обязательные поля, корректные даты, неотрицательные значения, поддерживаемые форматы фото. Недопустимые данные не перезаписывают дневник.

### Автоматическая проверка
На каждом push в main выполняется GitHub Actions «Offline PWA tests» с командой node --test tests/smoke.test.mjs.

Проверяются работа приложения с существующими данными, календарь, порции, копирование рациона, рецепты, офлайн-файлы, резервное сохранение и обработка ошибок квоты. Это не заменяет финальный тест в Safari на iPhone.

### Важно
- Персональные записи и фотографии не отправляются в GitHub.
- Локальная автокопия находится в том же браузере и не защищает от удаления приложения или очистки сайта. Периодически экспортируйте JSON в надёжное место.
- AI-анализ фотографий пока не подключён: для него нужен защищённый backend и поставщик модели с ключом вне публичного репозитория.
- Не объявлять эту промежуточную сборку окончательной версией без проверки на реальном iPhone.


## Конструктор блюд и фото — промежуточный этап

Реализовано в браузере, без запросов к внешним сервисам:

- **Составление блюда из ингредиентов.** Раскрой «Составить блюдо из ингредиентов» при добавлении еды, выбери продукты из встроенного или личного справочника, укажи граммы и нажми «Заполнить калории и БЖУ». Перед сохранением данные можно исправить вручную.
- Состав (список ингредиентов с порциями и значениями на 100 г/мл) сохраняется в записи как необязательное поле ingredients. Старые записи остаются совместимыми. Сохранённый состав можно снова просмотреть при редактировании.
- Снимок показывается перед сохранением. Поддерживаются JPEG/PNG/WebP и HEIC/HEIF, если браузер способен их декодировать. Файл должен быть не больше 25 МБ; результат конвертируется в JPEG и сжимается до 720 пикселей по длинной стороне. Сложные файлы, которые остаются слишком объёмными, отклоняются.
- Снимки **не** отправляются на сервер или в ИИ. Текущая сборка продолжает хранить их в localStorage; резервная копия JSON по-прежнему необходима.
- При открытии новой формы старый временный предпросмотр очищается. Дополнительная проверка JSON не допускает некорректный список ингредиентов.

### Что ещё не сделано

Распознавания еды по фотографии пока нет. Для него нужен защищённый backend, провайдер модели, ограничение затрат и явное согласие пользователя на передачу снимка. Конкретный план: [docs/photo-ai-roadmap.md](docs/photo-ai-roadmap.md).

**Не нужно переустанавливать PWA после каждого изменения.** Сборка продолжает развиваться; это не завершённый пользовательский релиз. Дальнейшая проверка в Safari на реальном iPhone потребуется перед финальным выпуском.

### Контроль качества

В GitHub Actions запускаются Node.js регрессионные тесты после обновлений: проверяются совместимость данных, календарь, копирование блюд, собственные продукты, составной рецепт, импорт, лимиты изображений и локальное кодирование JPEG. Важно: успешные тесты кода не означают, что все взаимодействия проверены на реальном iPhone.


## Backend для распознавания еды по фото — подготовлен, НЕ включён

На 8 ноября 2026 года серверная заготовка находится в каталоге [server](server/README.md). Результат — **ориентировочные диапазоны**, требующие подтверждения человеком. Изображения сервером не сохраняются.

GitHub Pages — статический хостинг. **Сервер ещё не запущен**, кнопка ИИ в PWA не подключена, API-ключ не добавлен, реальные платные запросы не выполнялись. Перед публичным запуском необходимы отдельный HTTPS-хостинг, безопасная аутентификация, общий для всех экземпляров лимитер и контроль расходов. Нельзя вставлять общий токен или API-ключ в публичный JavaScript.

Тесты: `node --test tests/*.test.mjs` (дневник + сервер, внешние запросы к OpenAI замоканы). См. [архитектурный план](docs/photo-ai-roadmap.md).


## Подготовленный клиентский интерфейс AI (выключен)

- `ai-config.js` содержит **пустой адрес сервера**. Кнопка анализа фото остаётся скрытой, пока отдельно не настроен доверенный HTTPS-адрес API. Токены и ключи в публичный репозиторий не включены.
- `ai-client.js` реализует добровольную отправку фотографии: пользователь выбирает фото, нажимает кнопку, подтверждает передачу в AI-сервис и вводит приватный токен на текущий запрос. Токен **не сохраняется** в localStorage.
- При успешном ответе выводятся **оценочные диапазоны** веса, калорий и БЖУ. Отдельное нажатие переносит средние значения в редактируемую форму. Запись в дневник создаётся лишь после обычной кнопки «Сохранить».
- Пока backend не развернут и не настроена безопасная авторизация, кнопка скрыта; реальное ИИ-распознавание отсутствует. Не обещать рабочий ИИ до завершения хостинга, аутентификации и проверки стоимости.

## OpenAI-only помощник в «Моём рационе» (подготовлен, выключен)

Решение владельца проекта: встроить в PWA **только помощника на моделях OpenAI**, без OpenRouter и иных провайдеров. Прежний неиспользуемый модуль OpenRouter переведён в заглушку и не вызывается приложением. Это **отдельный** чат через OpenAI API, не копия текущего диалога ChatGPT и не использует подписку ChatGPT Plus.

- Новый раздел **«🤖 Помощник»** в нижнем меню. Код интерфейса — [coach-client.js](coach-client.js).
- Серверный модуль [server/coach.mjs](server/coach.mjs) реализует краткий русскоязычный разговор о рационе, рецептах, калориях и БЖУ через **только OpenAI Responses API**, с `store: false`, без автоматического изменения записей.
- По умолчанию сообщения передаются только по явному действию. Названия блюд, фотографии и история дневника автоматически не отправляются. Отдельная опция позволяет передать **только суммы калорий и БЖУ за 7 дней**, после дополнительного подтверждения.
- Контент диалога не записывается в localStorage или GitHub. Сервер не ведёт журналов содержания обращений. Приватный токен запрашивается на текущий запрос и в приложении не сохраняется.
- **И чат, и фотоанализ отключены**, пока нет безопасно размещённого HTTPS-backend и утверждённого бюджета. Пустой [ai-config.js](ai-config.js) не содержит адрес сервера или секретов. Без подключения отправка заблокирована. Платных запросов не делали.
- Ограничения на запросы текущего шаблона хранятся в памяти одного процесса и **не являются надёжным денежным лимитом**. Перед публичным запуском необходимы безопасная аутентификация без ручного токена, устойчивые межпроцессные лимиты, оповещения об использовании и жёсткие ограничения бюджета у API-провайдера.

Для проверки используйте `node --test tests/*.test.mjs` — всё работает с подставными ответами, без реальных расходов. Финальная проверка в Safari на iPhone ещё не проводилась.


## Утверждённый пилот: $5, Cloudflare Free и OpenAI

9 ноября 2026 пользователь **одобрил первый бюджет $5**, без автоматических дополнительных платежей. Это согласование лимита, а не подтверждение совершённой оплаты. ChatGPT Plus не оплачивает OpenAI API.

- Подготовлена конфигурация [wrangler.jsonc](wrangler.jsonc) для **Cloudflare Workers Free** с SQLite-backed Durable Object. Платный Worker не требуется в пределах бесплатных квот.
- [cloudflare/worker.mjs](cloudflare/worker.mjs) — защищённые маршруты чата и анализа фото только через OpenAI (GPT-6.1 Terra). OpenAI API-ключ и личный токен существуют только как Cloudflare Secrets, не в публичном JavaScript.
- [cloudflare/budget.mjs](cloudflare/budget.mjs) — постоянный бюджетный реестр. При каждом запросе сначала резервирует сумму, после успешного ответа OpenAI учитывает фактические токены с запасом 30%. При недоступном реестре платные запросы блокируются. Встроенный месячный предел: $5.
- 3 запроса/мин, 20 запросов/сутки; не более $5 по локальной консервативной оценке. Это **не абсолютный лимит счета**: дополнительно нужен enforced hard limit $5 в OpenAI API и выключенное prepaid auto-reload.
- [Инструкция безопасного запуска](cloudflare/README.md). Старый Node HTTP сервер не использовать с платным API: он не имеет постоянного бюджета.
- **Сервер до сих пор не развёрнут**, реальные кредиты API не покупались, клиент [ai-config.js](ai-config.js) остаётся отключённым. Нельзя объявлять фотоанализ или чат с OpenAI работающими до завершения настройки, оплаты и теста.


## Добавление записи из чата

Для сохранения отдельных оценок питания, обсуждаемых с ChatGPT, **без удалённого доступа к данным iPhone** добавлен безопасный импорт одной записи через локальный код или URL-фрагмент.

- В разделе «Сегодня → Быстро добавить → 📥 Добавить запись из чата» можно вставить код формата `meal:...` и подтвердить запись. Открытие специальной ссылки с `#meal=...` также предлагает импорт. URL-фрагмент не отправляется серверу GitHub Pages.
- Импорт проверяет дату, тип, название, калории, БЖУ; не допускает повторного сохранения записи с тем же ID, не стирает прежние блюда, вес и настройки, не передаёт фотографии. Подтверждение пользователя обязательно.
- Данные записываются **только в локальное хранилище той копии приложения, которая открыта**. На iPhone Safari и установленное на домашний экран PWA могут использовать раздельные хранилища. Поэтому **ссылка, открывшаяся в Safari на iPhone, больше не сохраняет запись автоматически**: сначала показывает безопасный предпросмотр и предлагает скопировать код в установленный дневник. В PWA ссылка по-прежнему требует подтверждения.
- Этот механизм **не предоставляет ChatGPT удалённый доступ** к личному дневнику и не означает, что запись сохранена на iPhone до действия пользователя. Автоматической облачной синхронизации нет. Сообщения и коды из чата могут оставаться в истории беседы; в публичный репозиторий персональные записи не добавляются.


## Финальная проверка и обновления PWA (кандидат на релиз)

- Встроенная кнопка **«Обновить приложение»** появляется, когда сервис-воркер обнаруживает новую версию. Она перезагружает страницу, не очищая локальные записи. Переустановка приложения на экран Домой не требуется.
- Офлайн-оболочка кеширует страницы и JavaScript. Для первого открытия и поиска новой версии нужен интернет.
- Тесты Node: `node --test tests/*.test.mjs`. Дополнительно GitHub Actions запускает **реальный Chromium** через Playwright (совместимая Ubuntu 24.04) на локальной копии сайта шириной 390 px. Проверяются переходы между экранами, сохранение и перезагрузка, импорт по ссылке в браузере iPhone и в режиме PWA, а также офлайн-запуск. Никаких реальных личных данных или API-ключей для этого не используется.
- Автоматические тесты не подтверждают поведение Safari на физическом iPhone. Финальная проверка на устройстве нужна **один раз**: убедиться, что в установленном PWA есть записи, импорт по коду работает и JSON можно сохранить. Не очищать Safari/PWA до экспорта.


## Критерии выхода из 2.0 RC (архив)

Функции бесплатного дневника, импорта из ChatGPT, офлайн-режима и обновления без переустановки реализованы. Регрессионные тесты Node и Chromium в GitHub Actions должны быть зелёными перед публикацией.

**Ограничение релиз-кандидата:** Chromium на узком экране — не то же самое, что Safari в установленном на iPhone PWA. Перед названием «стабильная 2.0» остаётся один контрольный пользовательский прогон на настоящем устройстве: проверить сохранённые записи, импорт одной тестовой записи через код, экспорт JSON и сохранность дневника после обновления. Ничего не удалять и не сбрасывать.

Платный backend OpenAI/Cloudflare не развёрнут; приложение не отправляет записи или фото на серверы ИИ самостоятельно. Эти незапущенные модули остаются в репозитории отдельно и не включены в пользовательский интерфейс.
