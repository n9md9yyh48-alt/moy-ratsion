# Мой рацион — PWA для iPhone (версия 1.2)

Статическое PWA без платных сервисов. Откройте index.html для локального теста; для установки на iPhone опубликуйте папку на HTTPS-хостинге (например, GitHub Pages / Cloudflare Pages), затем откройте в Safari → Поделиться → На экран Домой.

## Реализовано
- Локальный дневник питания, фото, калории, БЖУ и напитки.
- Учёт веса, график, просмотр и редактирование измерений; отчёт за 7 дней.
- Календарь: выбор даты, переход по дням и месяцам, просмотр дневника за любой день.
- Быстрое добавление недавних и избранных блюд без повторного ввода БЖУ.
- 100 ориентировочных рецептов (30 исходных + 70 дополнительных), поиск по названию, ингредиентам и избранному, добавление в дневник.
- Редактирование целей, резервная копия JSON, восстановление и удаление.
- PWA и кэширование для офлайн-доступа после первого открытия.

## Ограничения
- Фото **не распознаются ИИ**: расчёты вводятся вручную.
- Нет синхронизации между устройствами и интеграции с ChatGPT.
- Данные и фото находятся в localStorage текущего браузера; при очистке данных браузера или удалении приложения они могут быть потеряны. Нет синхронизации или серверных копий. Регулярно экспортируйте резервную копию JSON.
- Версия 1.2 проверяет успех каждой записи. Если память переполнена, прежний дневник остаётся нетронутым. Автокопия создаётся только для небольших дневников (до 350 000 символов), при наличии свободной памяти; она остаётся на том же устройстве и **не заменяет** выгрузку JSON.
- Значения калорийности рецептов ориентировочные, не рассчитаны по точным граммовкам.
- Приложение не заменяет врача или диетолога.

### Ручная проверка после обновления
1. До обновления скачать резервную копию через «Отчёты» → «Скачать JSON».
2. Выбрать в календаре вчера и добавить блюдо; проверить, что оно не появилось в сегодняшнем списке.
3. Быстро повторить блюдо и добавить его в избранное; убедиться, что калории и БЖУ сохранились.
4. Создать запись веса, изменить дату или вес и удалить тестовое измерение.
5. Экспортировать JSON, проверить что файл скачался; при необходимости восстановить в другом браузере через настройки.

Состояние данных и фотографий НЕ загружается в GitHub. Приложение остаётся полностью локальным.

## Промежуточная сборка после 1.2 — доработка без переустановки

Пользователь решил не переустанавливать приложение на iPhone после каждого изменения. Разработка и автоматические проверки ведутся в GitHub, без обязательного тестирования на устройстве до финального релиза.

Добавлено:
- Офлайн-справочник 73 продуктов с **ориентировочными** калориями и БЖУ на 100 г/мл. В форме записи выбирается продукт и масса порции. Пищевая ценность готовых блюд зависит от состава и масла, поэтому значения следует сверять с этикеткой и фактической рецептурой.
- Кнопка копирования вчерашнего рациона на выбранную дату (без фотографий, с подтверждением).
- 100 рецептов, включая 70 новых со списками ингредиентов и способами приготовления. Поиск по ингредиентам показывает совпадения, но **не гарантирует**, что дома есть всё необходимое. У новых рецептов калории ориентировочные и не являются точным расчётом по фактической массе ингредиентов.
- Избранные рецепты, фильтры и постраничный вывод по 20 рецептов для удобства на смартфоне.
- Недельная диаграмма калорий и усреднённые БЖУ по заполненным дням; отсутствие записей **не означает** нулевое потребление.
- Информация о размере локального хранилища, количестве записей и фото.
- Строгая проверка дат, корректное различение ошибки сохранения и ошибки перерисовки интерфейса.
- «Мои продукты»: сохранение введённого продукта как локального шаблона с БЖУ на 100 г/мл, быстрый поиск, пересчёт порции, замена и удаление из справочника. Личные продукты входят в JSON-экспорт.
- Удаление фотографии из существующей записи о еде без удаления записи; обычные правки оставляют фото на месте.
- Усиленная проверка при восстановлении из JSON и локальной автокопии: обязательные поля, корректные даты, неотрицательные значения, поддерживаемые форматы фото. Недопустимые данные не перезаписывают дневник.

### Автоматическая проверка
На каждом push в main выполняется GitHub Actions «Offline PWA tests» с командой node --test tests/smoke.test.mjs.

Проверяются работа приложения с существующими данными, календарь, порции, копирование рациона, рецепты, офлайн-файлы, резервное сохранение и обработка ошибок квоты. Это не заменяет финальный тест в Safari на iPhone.

### Важно
- Персональные записи и фотографии не отправляются в GitHub.
- Локальная автокопия находится в том же браузере и не защищает от удаления приложения или очистки сайта. Периодически экспортируйте JSON в надёжное место.
- AI-анализ фотографий пока не подключён: для него нужен защищённый backend и поставщик модели с ключом вне публичного репозитория.
- Не объявлять эту промежуточную сборку окончательной версией без проверки на реальном iPhone.


## Конструктор блюд и фото — промежуточный этап

Реализовано в браузере, без запросов к внешним сервисам:

- **Составление блюда из ингредиентов.** Раскрой «Составить блюдо из ингредиентов» при добавлении еды, выбери продукты из встроенного или личного справочника, укажи граммы и нажми «Заполнить калории и БЖУ». Перед сохранением данные можно исправить вручную.
- Состав (список ингредиентов с порциями и значениями на 100 г/мл) сохраняется в записи как необязательное поле ingredients. Старые записи остаются совместимыми. Сохранённый состав можно снова просмотреть при редактировании.
- Снимок показывается перед сохранением. Поддерживаются JPEG/PNG/WebP и HEIC/HEIF, если браузер способен их декодировать. Файл должен быть не больше 25 МБ; результат конвертируется в JPEG и сжимается до 720 пикселей по длинной стороне. Сложные файлы, которые остаются слишком объёмными, отклоняются.
- Снимки **не** отправляются на сервер или в ИИ. Текущая сборка продолжает хранить их в localStorage; резервная копия JSON по-прежнему необходима.
- При открытии новой формы старый временный предпросмотр очищается. Дополнительная проверка JSON не допускает некорректный список ингредиентов.

### Что ещё не сделано

Распознавания еды по фотографии пока нет. Для него нужен защищённый backend, провайдер модели, ограничение затрат и явное согласие пользователя на передачу снимка. Конкретный план: [docs/photo-ai-roadmap.md](docs/photo-ai-roadmap.md).

**Не нужно переустанавливать PWA после каждого изменения.** Сборка продолжает развиваться; это не завершённый пользовательский релиз. Дальнейшая проверка в Safari на реальном iPhone потребуется перед финальным выпуском.

### Контроль качества

В GitHub Actions запускаются Node.js регрессионные тесты после обновлений: проверяются совместимость данных, календарь, копирование блюд, собственные продукты, составной рецепт, импорт, лимиты изображений и локальное кодирование JPEG. Важно: успешные тесты кода не означают, что все взаимодействия проверены на реальном iPhone.
